# Decisions

## Recommender / demo category: Office_Products (2026-10-22)

Chosen by measured size on the official Amazon Reviews 2023 5-core `last_out` files
(counts in `results/data_profile.md`):

| category | items | interactions | fits target (<=150K items, <=2M inter.) |
|---|---|---|---|
| Office_Products | 77,551 | 1,800,878 | yes |
| Sports_and_Outdoors | 156,235 | 3,472,020 | no |
| Toys_and_Games | 162,035 | 3,861,886 | no |

Electronics and Home_and_Kitchen are far larger and were not counted in full.

Other reasons: it is a mainstream shopping category that ESCI queries cover well, which helps
the ESCI-to-catalog transfer check in Phase 3. 66.8% of items have a price, giving a priced
demo catalog of 51,821 items.

## Recommender splits

The official benchmark ships 5-core `last_out` CSVs. We still build the split in code
(`cartrank.data.splits.leave_last_out`, unit-tested) so the rule is explicit, and it agrees
with the official valid/test files on 99.999% of rows (differences are timestamp ties).

## ESCI splits

US locale and `small_version == 1`. Dev = 10% of train `query_id`s (seed 0). The provided
test split is not used until Phase 7.

## Python

Python 3.12 pinned in `pyproject.toml` (per the playbook), managed with uv.

## Runtime artifacts on the Hugging Face Hub (2026-10-24)

Owner approved the upload. Repo: `abhibarnwal707/cartrank-artifacts`, **private** (about 300 MB: fine-tuned
encoder, slim catalog, catalog vectors, two-tower serving export, `config.json`). Private because the
Amazon Reviews 2023 dataset card states no licence and the catalog file carries Amazon product titles,
prices and image links. The Streamlit Cloud app downloads it at start-up with an `HF_TOKEN` secret;
use a fine-grained read-only token for that, not the write token. The raw datasets are not uploaded.

## Frontend design (2026-10-24)

Direction dealt by the taste-skill: "The sentence is the layout" (sector ai-product, tone editorial).
Idea: the visitor's own query becomes the poster-scale sentence; its parsed constraints become flat
tokens, the narrowing is drawn from the query's real candidate counts, and the ten result photos sit in
the headline where "ten" would go. Hanken Grotesk 400/500, greys and mint, square corners.

Decisions and why:
- Streamlit stays (stack unchanged); the design is injected as CSS (`app/style.css`) and markup
  (`app/ui.py`) through `st.html`, with a forced light theme (`.streamlit/config.toml`) so widgets never
  flip dark on a dark-mode OS.
- The first screen replays four precomputed responses (`app/examples.json`, regenerated by
  `python -m cartrank.serve.examples`), so it opens without loading models or spending LLM tokens.
- Every string from the catalog, the model or the visitor is HTML-escaped (tested by parsing the output).
- No video: no honest clip of the subject exists; motion comes from the product photographs themselves.
- Google Fonts is loaded by CSS import with a system sans fallback; not yet verified on Streamlit Cloud.
- streamlit is pinned to 1.66.1 in `app/requirements.txt` because the CSS targets its test ids.

## Frontend layout revision (2026-10-24)

Owner feedback on the live poster-style page: features were all at the bottom and the products were far too
large. Switched to the taste-skill's app-screen rules (achromatic ledger style, no-sidebar shell): tabs
(Search / Recommend / How it ranks) at the top, search box and example chips directly under a 32px title,
compact 80px-photo result rows beside a rail ("What it understood", "How it narrowed", "Under the hood").
Kept: Hanken Grotesk, mint accent, replayed examples, escaping. Dropped: poster-scale type, full-bleed rank 1.
Streamlit 1.66 tabs are react-aria (`[role=tablist]`, `[data-testid=stTab]`), not BaseWeb.
